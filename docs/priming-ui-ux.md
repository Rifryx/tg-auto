## 1. Позиционирование и общий принцип

- Конкурент выглядит как «панель настроек с кнопкой купить»: длинный
  вертикальный скролл, все секции равнозначны, статус кампании внизу.
- Мы делаем **studio-подход**: экран кампании — рабочее место с рельсами.
  Сверху постоянная шапка кампании, слева — навигация по проектам,
  справа — «живой» рельс с логами и метриками. Настройки — в центре,
  разбиты на шаги, а не в одну простыню.
- Основной сценарий: «настроил → нажал Play → смотрю, как идёт», а не
  «крутил колесо мышки 2 минуты, чтобы найти кнопку запуска».

Ключевая мысль: **прайминг — это living operation**, а не разовая
отправка. Значит UI должен показывать процесс, а не только форму.

## 2. Информационная архитектура

Модуль состоит из четырёх верхнеуровневых сущностей. Пункт бокового
меню — **«Прайминг»** с иконкой bell-inside-shadow (мягкая волна вокруг
колокольчика, показываем «звук без сообщения»).

```
Прайминг
├── Кампании          — список активных/архивных задач
│   ├── Новая         — визард (см. §5.2)
│   └── Кампания/{id} — детальный экран (см. §5.3)
├── Профили           — каталог preset'ов POC (см. §5.4)
├── Аудитория         — каталог собранных списков + blacklist (см. §5.5)
└── Инсайты           — сквозной дашборд по всем кампаниям (см. §5.6)
```

Отличие от конкурента: у него в одном экране «Масстегинг» намешаны
аккаунты, цели, профиль, темп и логи. У нас — четыре пространства,
каждое с собственной ролью. Внутри кампании — те же блоки, но как
навигируемые шаги, а не свалка.

## 3. Layout: чем отличаемся от конкурента

### 3.1 Что убираем

- Гигантскую оранжевую полосу «Купить модуль» посреди экрана. Пейволл
  — тонкий баннер сверху, до первого шага мастера. Не крадёт фокус.
- Верхний рекламный блок «Это превью модуля». Заменяем на dev-toggle в
  углу.
- Дубликат кнопок «остановлено / купить / отменить зависшие задачи»
  внизу. Управление — только в шапке кампании и на карточке в списке.

### 3.2 Что вводим

- **Sticky Campaign Header** — постоянно виден: имя, статус
  (пульсирующая точка), Play/Pause/Stop, прогресс-бар, ETA. Не скроллится.
- **Right-rail «Пульс»** — постоянный live-стрим (счётчики + лента
  событий). Скрывается по кнопке, но помнит состояние.
- **Left-rail «Ресурсы»** — быстрый доступ к пулу аккаунтов, к списку
  целей, к preset'ам. Открывается drawer'ом, не отдельным экраном.
- **Центральный поток** — не одна простыня, а шаги-«карточки»
  (Триггер → Аккаунты → Аудитория → Профиль → Темп → Humanizer →
  Автостоп). Между шагами — валидаторы; шаг подсвечен, пока в нём есть
  ошибка.

### 3.3 Grid

- Desktop ≥ 1440: 3 колонки `72–560–360`, gutters 24 px.
- Desktop 1024–1440: 2 колонки, right-rail сворачивается в
  выдвижную панель.
- Tablet 768–1024: одна колонка, шапка липкая, rail'ы — модалки.
- Mobile < 768: bottom-tab на 3 вкладки (Настройка / Пульс / Логи),
  шапка кампании становится компактной.

## 4. Дизайн-язык

### 4.1 Цвета (роли, не тон)

- `bg.canvas` — глубокий тёмный (`#0B1220`-семейство). Не «серый», не
  «синий-неон».
- `bg.surface` — на 6% светлее, для карточек.
- `bg.raised` — на 12% светлее, для активной карточки шага.
- `text.primary` / `text.secondary` / `text.muted`.
- Акценты — **три состояния**, не одно:
  - `accent.action` (запуск, primary): холодный сине-фиолетовый.
  - `accent.info` (метрики, прогресс): бирюзовый.
  - `accent.attention` (превышение лимитов): янтарный.
  - `accent.danger` (карантин, флудвейт): коралловый, не «алый».
  - `accent.success` (primed, healthy): мятный.
- Никаких «купить сейчас»-оранжевых заливок под важным контентом.

Светлая тема — производная (инвертируем `bg.*`, оставляем те же акценты
с уменьшенной насыщенностью).

### 4.2 Типографика

- Заголовки: sans-serif с высокой контрастностью, но не «жирный
  дефолт» из Tailwind. Веса: 500 для заголовков, 600 для чисел
  метрик, 400 для body.
- Числа-метрики — моноцифры (`font-variant-numeric: tabular-nums`),
  чтобы счётчики не «прыгали».

### 4.3 Радиусы, тени, движение

- Радиусы: карточка 16 px, кнопка 10 px, chip 999 px, input 12 px.
- Тени — не тяжёлые. Один уровень elevation для raised-карточек.
- Движения: 160–220 ms, `cubic-bezier(0.2, 0.8, 0.2, 1)`. Никаких
  «пружин» и `spring` на утилитарных элементах.

### 4.4 Иконография

Свой набор outline-иконок (16/20/24). Ключевые:

- «Прайминг» — колокольчик с волной.
- «Триггер» — восклицательный знак в скобках-скобках (эффект пинга).
- «Аудитория» — три точки-профиля с фильтром.
- «Профиль POC» — карточка визитки.
- «Humanizer» — след ноги.
- «Карантин» — щит с точкой.

## 5. Ключевые экраны

### 5.1 Экран «Кампании» (список)

Не таблица, как у конкурента, а **карточки-строки** с встроенным
живым виджетом. Каждая карточка отдаёт:

- Имя, статус (пульсирующая точка), возраст.
- Sparkline «праймы за 24ч».
- Три числа: `отправлено / успех% / карантин`.
- Компактный `Play/Pause` без входа внутрь.
- Правый край карточки — «свеча здоровья» аккаунтов (мини-диаграмма
  из активных/cooldown/quarantined).

Тулбар: поиск, фильтры по статусу и тегам, сортировка. FAB
«+ Новая кампания» — в правом нижнем углу, а не отдельная кнопка в
таблице (сохраняем фокус).

### 5.2 Экран «Новая кампания» (визард)

**Не длинный скролл.** Шаги как pill-навигация сверху:

`1. Основа → 2. Триггер → 3. Аудитория → 4. Профиль → 5. Темп →
6. Humanizer → 7. Автостоп → 8. Обзор`

Каждый шаг — карточка на всю ширину, с левой панелью-«помощник»:
короткий пояснительный блок и «Что видит целевой пользователь»
(live-превью, если применимо).

Особенности отдельных шагов:

- **Шаг 2. Триггер**. Радио-группа с иконками. Каждый вариант —
  карточка с превью push-уведомления на моке телефона (два табика:
  iOS / Android). Показываем, что именно увидит цель. Никто из
  конкурентов такого не делает.
- **Шаг 3. Аудитория**. Три source-tab'а: `Парсер чата / CSV /
  Ручной список`. Для парсера — форма и кнопка «Пропарсить», после —
  карточка с `raw / after filters` и кнопкой «Использовать 4 812
  целей». Ниже — блок фильтров: username, premium, бот, deleted,
  admin, last_seen — все в виде toggle-chips.
- **Шаг 4. Профиль POC**. Селект preset'а или «Создать». Внутри —
  визуальный **preview** карточки профиля Telegram (как выглядит у
  цели, когда она перейдёт), с редактируемыми полями «на месте».
- **Шаг 5. Темп**. Двусторонний слайдер `delay_between_targets` +
  цифры `daily_limit_per_account`, `flood_wait_pause`,
  `max_flood_waits_per_account`. Селект warm-up profile
  (`cold / warm / hot`) — авто-подставляет цифры и подсвечивает,
  что изменилось.
- **Шаг 6. Humanizer**. Enum + чекбоксы по действиям. Справа —
  «прогноз активности» (сколько чтений/реакций в час).
- **Шаг 8. Обзор**. Читаемая сводка + чек-лист безопасности
  (см. §8.4). Кнопка «Запустить» становится активной, только когда
  все чекбоксы зелёные.

### 5.3 Экран «Кампания/{id}»

Открывается по клику из списка. Layout:

- **Sticky header**: имя + inline-редактирование, статус, Play/Pause/Stop,
  прогресс `X / Y целей`, ETA, кнопка «Настройки» (открывает drawer'ом
  тот же визард, но с прыжком к нужному шагу).
- **Center**: табы `Обзор / Аккаунты / Цели / Профиль POC / Логи`.
  - Обзор — большие метрики и графики.
  - Аккаунты — таблица с состоянием, `primes_today`,
    `next_available_at`, кнопки «карантин»/«вернуть».
  - Цели — виртуальная таблица с фильтрами по outcome; массовые операции.
  - Профиль POC — какой preset используется, «применить к N».
  - Логи — виртуализированный список; фильтры по outcome/аккаунту/окну
    времени; экспорт CSV.
- **Right-rail «Пульс»**: live-стрим событий (SSE/WS), четыре крупных
  KPI-плитки, «тревоги» (privacy_rate растёт, аккаунт X в карантине).

### 5.4 Экран «Профили» (POC)

- Каталог карточек-preview: «как выглядит профиль у цели». Клик —
  drawer с редактором.
- Визард создания preset'а: шаги `Имя → Аватар → Username → Bio →
  Stories → Anchor-канал`. На каждом шаге — превью справа.
- Bulk-панель «Применить к аккаунтам»: чек-лист аккаунтов + прогресс
  применения по каждому пункту (аватар ✓, username ✓, stories ✓,
  anchor ✗ retry).

### 5.5 Экран «Аудитория»

- Каталог собранных списков (по всем кампаниям пользователя): источник,
  когда собран, сколько живых после фильтров, кнопка «переиспользовать
  в новой кампании».
- Blacklist manager: поиск по username/id, массовые действия, теги
  причин (privacy_restricted, complaint, bot).

### 5.6 Экран «Инсайты»

Сквозной дашборд, аналогов у конкурента нет (у него — только per-task
статистика). Показывает:

- Топ-триггеры по success-rate.
- Динамику privacy_rate во времени (чтобы поймать, когда Telegram
  «зажимает» механику).
- Health по аккаунтам (сколько дней без карантина, сколько FLOOD_WAIT
  за 30 дней).
- Календарь суточной нагрузки (heatmap час × день недели).

## 6. Микровзаимодействия и состояния

- **Пульсирующая точка** статуса кампании — единственная анимация на
  экране, которая идёт постоянно (0.9s → 1.4s ease-in-out).
- **Optimistic Play/Pause**: клик мгновенно меняет вид кнопки; фактическое
  состояние подтверждается через WS в течение 1–2s, при ошибке —
  toast + откат.
- **Live-counters** — плавный tween целых чисел; не «прыжок с 421 на 423».
- **Toast'ы** — правый нижний угол, не перекрывают live-rail; auto-dismiss
  4s; для ошибок — «Подробности» → drawer.
- **Skeletons** вместо спиннеров при загрузке таблиц.
- **Empty states** — не «нет данных», а «Здесь появится...», с CTA
  «Создать первый preset».

Ошибочные состояния:

- `USER_PRIVACY_RESTRICTED > X%` → баннер в центре шапки:
  «Много цели с закрытой приваткой. Смените источник?» + кнопка.
- Аккаунт в карантине → в таблице аккаунтов бейдж «квартинтин» с
  countdown до `next_available_at`.
- Anchor-канал сломался → в POC preview красный badge и «Пересоздать».

## 7. Мобильная адаптация

- Bottom-tab (3 вкладки): **Настройка / Пульс / Логи**.
- Sticky header кампании ужимается: имя + статус-точка + компактная
  кнопка Play/Pause; Stop — во всплывающем меню.
- Right-rail «Пульс» превращается во вкладку.
- Визард — вертикальная колонка step-by-step, с крупными кнопками
  «Далее» внизу и прогресс-баром сверху.
- Все таблицы (аккаунты, цели, логи) — карточки, не строки.

## 8. Идеи «лучше, чем у конкурента»

Ниже — конкретные фичи, которые ставят наш модуль выше:

### 8.1 Push-Preview для триггера

Показываем на моке iOS/Android, **какой именно текст пуш-уведомления**
увидит цель для выбранного `trigger_action`. Ни в одном конкурентном
решении не показывают ни превью, ни отличий между iOS и Android.
Помогает понять, какой триггер даёт бóльший CTR (у Android/iOS текст
пушей отличается).

### 8.2 Simulator Mode (dry-run на воркере)

Кнопка «Прогнать без отправки». Оркестратор строит расписание, но
`trigger.run` возвращает fake outcomes из статистической модели.
Пользователь видит:

- Сколько времени займёт кампания.
- Сколько цели «отвалятся» по privacy (оценка по историческим данным).
- Расчёт лимитов «влезем ли за N дней».

Идеально ловит ошибки конфига до реальных FLOOD_WAIT.

### 8.3 Автопилот темпа (Adaptive Rate)

Не фиксированный `delay 20–60s`, а адаптивный: если `privacy_rate`
растёт — авто-замедление; если чисто — плавное ускорение. Отдельный
toggle «Автопилот». Показываем текущий множитель в UI («Темп ×0.7 —
скачок privacy_rate»). У конкурента только ручные ползунки.

### 8.4 Safety Checklist перед стартом

На шаге «Обзор» — интерактивный чек-лист с автопроверками:

- Все аккаунты прогреты ≥ N дней?
- Прокси у аккаунтов подключён и alive?
- POC-профиль применён к каждому аккаунту (аватар/username/anchor)?
- Anchor-канал не 404?
- Blacklist свежий (< 30 дней)?
- В целях доля username < 100% — предупредить.

Пока хоть один пункт красный — Play неактивен. Удерживает от «выстрелил
себе в ногу».

### 8.5 Живая «heatmap рисков» на дашборде

Календарь час × день недели с плотностью FLOOD_WAIT. Пользователь
видит, что «по средам вечером» FLOOD растёт и планирует запуски вне
этого окна.

### 8.6 Split-Test триггеров (A/B)

Кампания может быть запущена сразу с двумя `trigger_action`.
Оркестратор равномерно раскидывает цели между ними; в статистике —
success-rate по каждому. Помогает выбрать самый рабочий пуш «здесь и
сейчас», Telegram меняет реакции чаще, чем нам присылают отзывы.

### 8.7 «Profile Fitness Score»

Рейтинг оформления профиля (аватар без phash-коллизий, bio не пустое,
anchor-канал ≥ 1 пост, есть stories) — 0..100. Аккаунты с низким
рейтингом подсвечиваются, кампания вежливо ругается: «У 3 аккаунтов
пустой bio — конверсия упадёт».

### 8.8 Attribution-луп через bot-стартер

Оффер в bio — ссылка `t.me/<bot>?start=<campaign_id>_<account_id>`.
Модуль слушает старты нашего бота и матчит их с активными кампаниями.
На дашборде появляется реальный CTR по кампаниям. Конкурент этого не
делает — считает только «отправлено», но не «конвертировалось».

### 8.9 Recipe Library

Готовые пресеты кампаний (triggers + темпы + humanizer) под сценарии:
`«Мягкий прогрев» / «Массовый прайминг» / «Точечный по премиумам»`.
Один клик — заполнен весь визард. Плюс — «поделиться рецептом»
(экспорт JSON).

### 8.10 Anti-cannibalization

Отдельный toggle: «Не праймить цель, если она уже была задета в
масстегинге/шиллинге за N дней». Технически — просто общий blacklist
по проектам пользователя. Конкурент модули не связывает.

### 8.11 Timeline вместо «просто логов»

Логи — не таблица, а вертикальный timeline: аккаунт → target → outcome,
с иконками. По одной цели — раскрытие «что именно произошло» (запрос,
ответ Telegram, следующая пауза). Экспорт — сохраняем.

### 8.12 Undo Last Batch

Если пользователь запустил и заметил ошибку, кнопка «Откатить последние
N праймов»: она не отменяет push у цели (уже случилось), но помечает
их `manually_reverted` и вычитает из daily-лимита, чтобы не влететь в
FLOOD.

### 8.13 «Ночной режим» аккаунта

Каждому аккаунту в кампании — окно активности (напр. 09:00–23:00 по
локали номера). Ночью humanizer тоже спит. Больше похоже на живого
пользователя, меньше сигналов для антифрода.

### 8.14 Explain-mode

На каждом слайдере/поле — маленький `?`. При клике — не просто подсказка,
а объяснение «что происходит на низком уровне» (например: «`FLOOD_WAIT_X`
приходит от MTProto, когда за 60s было >Y действий»). Учит пользователя.
Такого у конкурента нет — там просто «i».

## 10. Чек-лист доступности

- Все интерактивные элементы фокусируются с клавиатуры (`:focus-visible`).
- Все критические статусы дублируются иконкой + цветом (не только
  цветом — важно для дальтоников).
- Контраст текста ≥ 4.5:1 (WCAG AA) в обеих темах.
- Пульсирующая точка статуса уважает `prefers-reduced-motion`.
- Все `title`/`aria-label` есть у иконок-кнопок.
- Live-регион у `<PulseRail/>` (`aria-live="polite"`), чтобы screen
  reader сообщал о новых событиях без спама.
- Модалки: focus-trap, `Esc` закрывает, возвращает фокус на триггер.

## Итог

Мы не копируем расстановку конкурента (вертикальный скролл с оранжевой
кнопкой купить и логами внизу), а строим **studio-подход**: sticky-шапка,
левый rail ресурсов, правый rail «пульса», визард по шагам, свой
дизайн-язык (сине-мятная палитра, скруглённые карточки, tabular-nums для
чисел). Плюсом — 14 фич из §8, которых у конкурента нет: от Push-Preview
и Simulator Mode до Attribution-петли и Anti-cannibalization. Итоговый
модуль отличается не только визуально, но и функционально.
