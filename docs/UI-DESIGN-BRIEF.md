# UI Design Brief — Neuro-Commenting Mini App

Этот файл — источник истины по визуальному языку. Перед выполнением ЛЮБОГО
фронтенд-промпта (25–28 из PROMPTS-5-24.md) Claude Code должен:

1. Использовать плагин `frontend-design` (skills `design-review` /
   `frontend-design-principles`, если они так называются в установленной
   версии — проверь `/plugin installed` и применяй его общие принципы
   качества интерфейса).
2. Строго следовать конкретной палитре, типографике и компонентам,
   описанным НИЖЕ — они переопределяют дефолтные предпочтения плагина по
   цвету/форме, если он предложит что-то своё. Этот файл — не "вдохновение",
   а спецификация.

**Стиль одной фразой:** нативный iOS-тёмный, матовый, глубокий, строгий.
Не дашборд с неоновыми акцентами, не "AI-generic" с фиолетовыми градиентами
и стеклом (glassmorphism) — а как системные приложения Apple (Health,
Wallet, Kогда): истинно-чёрный фон, карточки на тон светлее с тонкой
обводкой вместо теней, минимум цвета, крупная плотная типографика.

---

## 1. Что категорически запрещено

- Фиолетовые/розовые градиенты в фонах и кнопках.
- Glassmorphism, blur-эффекты на карточках, неон, свечения (glow).
- Яркие насыщенные акцентные цвета как декор (только функционально —
  статус-индикаторы).
- Скругления меньше 12px на карточках — плоский "корпоративный" вид не нужен.
- Тени как основной способ показать глубину — глубина через границы
  (hairline borders) и небольшую разницу яркости фона, не через drop-shadow.
- Иконки с заливкой/многоцветные — только тонкие line-иконки, монохром.

## 2. Палитра (design tokens)

```css
/* Фон */
--bg-base: #050505;        /* истинно чёрный, не #000 (чуть теплее) */
--bg-elevated: #0F0F11;    /* второй уровень — модалки, дровер */

/* Поверхности карточек */
--surface-1: #141416;      /* базовая карточка */
--surface-2: #1C1C1F;      /* карточка внутри карточки / активный таб */
--surface-border: rgba(255,255,255,0.07);   /* hairline вместо тени */
--surface-border-strong: rgba(255,255,255,0.14);

/* Текст */
--text-primary: #F5F5F7;   /* не чистый белый — тёплый почти-белый */
--text-secondary: #8E8E93; /* iOS system gray */
--text-tertiary: #636366;

/* Функциональные цвета (ТОЛЬКО для статусов, нигде как декор) */
--status-active: #34C759;   /* аккаунт active/pool — зелёный iOS */
--status-warning: #FF9F0A;  /* cooldown/warming — янтарный iOS */
--status-critical: #FF453A; /* banned/health-алерт — красный iOS */
--status-neutral: #636366;  /* retired/created — серый */

/* Единственный "фирменный" акцент — используется ТОЧЕЧНО:
   основная кнопка действия, активный таб навбара, выделение выбранного */
--accent: #F5F5F7;          /* да, это просто белый на чёрном —
                                как в референсе с плюс-кнопкой (скрин 1)
                                и капсульным навбаром (скрин 2, 6) */
--accent-on: #050505;        /* текст/иконка НА акцентной поверхности */
```

Если нужен цветной бренд-акцент (не обязательно) — один холодный тон,
использовать так же скупо, как красный/зелёный в референсах платежей:
только на самом важном интерактивном элементе экрана, не более одного
цветного пятна на экран.

## 3. Типографика

- Шрифт: системный (`-apple-system, SF Pro`) с фолбэком Inter — не Google
  Fonts с засечками, не "дизайнерские" гарнитуры.
- Заголовок экрана (H1): 28–34px, вес 700, `letter-spacing: -0.02em`, как
  "Send" / "Workouts" / "Studio" в референсах — крупно, без подзаголовка
  под ним в большинстве случаев.
- Заголовок карточки/секции: 15–17px, вес 600.
- Тело: 14–15px, вес 400–500, `--text-secondary` для второстепенного.
- Цифры (KPI, суммы, счётчики) — `font-variant-numeric: tabular-nums`,
  вес 600–700, крупнее окружающего текста минимум на 20%.
- Подписи/метаданные (даты, статусы, единицы): 12–13px, `--text-tertiary`.

## 4. Карточки и структура

- Радиус карточек верхнего уровня: 20–24px.
- Радиус мелких элементов (бейджи, кнопки внутри карточки): 10–14px.
- Внутренний паддинг карточки: 16–20px, не экономь на воздухе — референсы
  держат карточки разреженными, а не плотно набитыми.
- Обводка: `1px solid var(--surface-border)` — это ЕДИНСТВЕННЫЙ способ
  отделить карточку от фона в состоянии покоя. Никаких box-shadow в
  дефолтном состоянии.
- Разделение между секциями экрана — не линиями, а расстоянием (24–32px
  вертикальный gap) и заголовком секции.
- Списки (например, лог комментов, лента активности) — каждая строка это
  мини-карточка с hairline-разделителем ИЛИ отдельные карточки с gap 8px
  между ними (см. референс "Receiving" — отдельные карточки, не таблица).

## 5. Нижняя навигация

Два референсных паттерна — используем **капсульный плавающий навбар**
(референсы 2 и 6: скруглённая "таблетка", не на всю ширину, с активным
табом на светлой/белой подложке внутри тёмной капсулы). Это выглядит
дороже и "серьёзнее" плоского full-width таббара (референс 1, 3).

Конкретно:
- Капсула: `background: var(--surface-1)`, border как у карточек, высота
  ~56–64px, горизонтальные отступы от краёв экрана 16–20px, плавает над
  контентом с небольшим нижним отступом (не приклеена к самому низу).
- Активный таб: подложка `var(--accent)` (белая), иконка/текст —
  `var(--accent-on)` (чёрный). Это ровно паттерн из референса 6
  (тёмная капсула, активный элемент — светлый овал).
- Неактивные табы: иконка `var(--text-secondary)`, без подписи текстом
  ИЛИ с подписью 10-11px под иконкой — выбери по месту, референс 3
  показывает подписи, референс 6 — без подписей (компактнее). Для 4
  табов (Главная/Аккаунты/Задачи/Ещё) с подписями будет читаемее —
  используй подписи.
- Safe-area-inset-bottom учтён, капсула не заезжает под системный индикатор
  свайпа iPhone.

## 6. Кнопки и интерактивные элементы

- Основная кнопка действия (create/submit): либо полноширинная капсула с
  `var(--accent)` фоном и `var(--accent-on)` текстом, либо круглая
  плавающая FAB (референс 3 — синий кружок с плюсом; у нас — белый кружок
  на `var(--accent)`, т.к. цветного акцента нет).
- Вторичные кнопки: `var(--surface-2)` фон, `var(--text-primary)` текст,
  без обводки или с hairline.
- Иконки-кнопки (маленькие круглые, как поиск/колокольчик в референсе 1):
  `var(--surface-2)` фон, круглые, 36–40px.
- Пилюли-фильтры (для списка аккаунтов по стадиям): неактивная —
  `var(--surface-1)` + hairline border + `var(--text-secondary)`;
  активная — `var(--surface-2)` + `var(--surface-border-strong)` +
  `var(--text-primary)` (НЕ белая заливка — пилюли-фильтры отличаются
  от табов навбара, чтобы не спорить визуально за внимание).

## 7. Статус-индикаторы (специфично для нашего приложения)

Стадии аккаунта (`created/warming/pool/assigned/cooldown/retired/banned`)
и здоровье — это данные, которые должны читаться мгновенно, одним взглядом,
через цвет + форму, без чтения текста:

- Маленькая точка-индикатор (8px circle) рядом с аккаунтом в списке:
  `pool`/`assigned` → `--status-active`; `warming`/`cooldown` →
  `--status-warning`; `banned` → `--status-critical`; `created`/`retired`
  → `--status-neutral`.
- Текстовый бейдж стадии (капсула с текстом) — фон это тот же цвет статуса
  на 15% прозрачности (`color-mix` или rgba), текст — сам статусный цвет
  полной насыщенности. Это стандартный iOS-паттерн "мягких" бейджей
  (сравни с зелёным/жёлтым/красным в референсе "Stock Overview" —
  In Stock/Low Stock/Out of Stock).
- Алерты на главном экране — карточка с левой цветной полосой (4px,
  `--status-critical` или `--status-warning`) вместо цветного фона всей
  карточки — так серьёзнее и спокойнее.

## 8. Графики (Портфель прогрева, лог активности)

Если понадобится линейный график (например, динамика прохождения прогрева
или объём комментов за неделю) — референс "Portfolio Performance" и
"Volume lifted" задают тон: тонкая линия (1.5–2px) `var(--text-primary)`
или `--status-active`, без заливки под линией ИЛИ очень лёгкая градиентная
заливка от цвета линии к прозрачности (5–10% opacity, не яркая заливка).
Сетка — едва видимые hairline, подписи осей — `--text-tertiary`, мелкий
шрифт.

## 9. Как применить к нашим 4 табам

- **Главная** — как референс "Send/Receiving": крупный заголовок,
  KPI-карточки в горизонтальный скролл (сводка по стадиям), затем
  вертикальные карточки-секции (алерты, активные модули, лента).
- **Аккаунты** — как референс "Workouts"/"Stock Overview": список
  карточек-строк с числами и статус-цветом, пилюли-фильтры сверху.
- **Задачи** (модули) — как референс grid карточек "All Drafts/2AM ideas":
  карточки-папки для каждого модуля/кампании с иконкой и счётчиком.
- **Ещё** — как референс "Proton Pass" настройки: список строк-пунктов
  с иконкой слева, шевроном справа, никакой сложной вёрстки.

```
Прочитай docs/UI-DESIGN-BRIEF.md ПЕРЕД тем как писать любой компонент.
Используй плагин frontend-design (его skills по общему качеству
интерфейса) КАК ДОПОЛНЕНИЕ к этому брифу, не вместо него — при конфликте
рекомендаций плагина и конкретных значений из UI-DESIGN-BRIEF.md
побеждает бриф (палитра, радиусы, навбар — зафиксированы конкретно).
```

Это гарантирует, что общие "хорошие практики" плагина (иерархия, отступы,
consistency) применятся ПОВЕРХ нашей конкретной палитры, а не подменят её
чем-то своим.
