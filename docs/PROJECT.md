## Отложенные TODO (DEFERRED)

### TODO #13 — Каталог целей для discovery по интересам персоны (2026-09-13)

**Где:** `worker/warming/actions/base.py` — `DISCOVERY_CHANNELS = ("telegram",
"durov", "tginfo")`, `DISCOVERY_GROUPS = (...)` (хардкод-плейсхолдер).

**Что откладываем:** выбор целей прогрева (подписки/чтение) по интересам персоны
вместо общего хардкода публичных каналов.

**Почему:** это v2-фича — каталог по интересам персоны требует отдельного
проектирования (модель интересов, источник каталога, маппинг persona → темы).
Для v1 достаточно набора общеизвестных публичных каналов: прогрев набирает
активность и доходит до `pool` без каталога. Функционально пайплайн не блокирует.

**Когда чинить:** когда появится модель интересов персоны и требование
«естественного» прогрева под нишу.

### TODO #14 — arq-задачи account.retire / account.acknowledge_ban (2026-09-13)

**Где:** `worker/tasks/handlers.py` — `TaskName.ACCOUNT_RETIRE`,
`TaskName.ACCOUNT_ACKNOWLEDGE_BAN` зарегистрированы как задачи-заглушки
(`_STUB_TASKS`, бросают `NotImplementedError`).

**Что откладываем:** реальные тела этих arq-задач.

**Почему:** функционально retire/acknowledge_ban уже работают синхронно через
API (`POST /accounts/{id}/actions/retire|acknowledge_ban` → state machine). Для
v1 синхронного пути достаточно; отдельные arq-задачи избыточны. Они понадобятся
только под сценарий массового retire (batch-операция), которого сейчас нет.

**Когда чинить:** при появлении batch-операций над аккаунтами (массовый
retire/acknowledge из UI или по расписанию) — тогда реализовать тела задач и
enqueue из API вместо синхронного пути.
