## 1. Принципы дизайна

Модуль встраивается в существующую систему проекта (`frontend/src/`),
поэтому берём её базу:

- **Тёмная и светлая темы** через CSS-переменные (`tokens.css`)
- **Радиусы**: `22px` (card), `12px` (chip), `pill` — уже в `tailwind.config.ts`
- **Типографика**: SF Pro / Inter, iOS-подобная иерархия
- **Цвета**: `surface-1/2`, `text-primary/secondary/tertiary`, `accent`, `status-*`
- **Мобайл-фёрст**: адаптация под 375px, `BottomNav` на мобиле,
  `DesktopSidebar` на lg+

### Философия
1. **Прогрессивное раскрытие**: не показываем 20 полей сразу — по мере
   готовности предыдущего блока открывается следующий.
2. **Wizard-first для новичка, one-page для эксперта**: 3-шаговый мастер
   при создании; после — единый экран для правки.
3. **Живое превью**: диалог виден в стиле Telegram-мессенджера в реальном
   времени, пока пользователь редактирует сценарий.
4. **Нулевой JSON и никаких «сырых» ID**: пользователь видит имена,
   аватарки, роли — не `campaign_id=42` и не raw-JSON редакторы.
5. **Каждый параметр — с пояснением**: `info`-иконка рядом с меткой
   раскрывает всплывающую подсказку (что это, почему важно, какое дефолтное).

## 2. Ключевые отличия от конкурента

Смотрим на скрины: у конкурента всё вываливается длинной вертикальной
портянкой (аккаунты → конфигурация → настройка → запуск → история →
ЧС) — тяжело сканировать глазами, легко потеряться.

**Наш подход** — другая структура:

| Аспект | Конкурент | Наш вариант |
|--------|-----------|-------------|
| Создание кампании | Одна длинная страница | **3-шаговый Wizard**: Основа → Сценарий → Запуск |
| Роли и шаги | Разделены на две секции | **Объединены в одну карточку**: роль слева, её реплики справа (Kanban-стиль) |
| Превью диалога | Отдельная кнопка «Превью» | **Живое превью справа на десктопе**, всегда видно (split-view) |
| Аккаунты + резерв | Отдельный тумблер «Резерв» | **Единый пул с drag-and-drop**: перетаскиваешь аккаунт из «Основные» в «Резерв» |
| Цели | Textarea со списком | **Chip-редактор**: каждый канал — отдельный чип, статус (✓ резолвнут / ⚠ ошибка / … загрузка) сразу видно |
| Запуск | Отдельный блок | **Плавающая нижняя панель** с чеклистом и Run-кнопкой, всегда виден прогресс готовности |
| История/ЧС | В самом низу той же страницы | **Отдельные табы** экрана: Обзор / Сценарий / Цели / История / ЧС |
| Сухой прогон | Кнопка «Проверить» | **Симулятор**: показывает пошагово, что и когда будет отправлено, с mock-таймингом |
| Ошибки/баны | Просто попадают в ЧС | **Инсайт-панель**: «5/20 аккаунтов забанены на →t.me/xxx, попробуй меньше задержку» |

## 3. Информационная архитектура

```
/modules/shilling                     — Главный экран (список кампаний)
├── /new                              — Wizard создания (3 шага)
└── /:id                              — Детали кампании (табы)
    ├── /overview                     — Обзор + быстрая правка
    ├── /scenario                     — Конструктор сценария
    ├── /accounts                     — Пул аккаунтов + распределение ролей
    ├── /targets                      — Целевые каналы
    ├── /history                      — Логи запусков + статистика
    └── /blacklist                    — Чёрный список
```

Плюс глобальные модалки:
- **Bottom-sheet «Выбор аккаунтов»** (переиспользуем из commenting)
- **Модалка «Сгенерировать сценарий»** (форма для LLM)
- **Модалка «Сухой прогон»** (симулятор)

### 4.2 Wizard создания (`/modules/shilling/new`)

Три шага с индикатором сверху:

```
    ①  Основа  ─────  ②  Сценарий  ─────  ③  Запуск
    ●═══════●═════════○═════════════════════○
```

#### Шаг 1: Основа
- Название кампании
- Бренд/ключевая фраза (input с подсказкой «Как это будет выглядеть»)
- Модель ИИ (SegmentedControl: DeepSeek / Gemini)
- Медиа (drop-zone для картинок к репликам, опционально)
- **CTA**: [Далее →]

#### Шаг 2: Сценарий (см. §5.1 «Split-view редактор»)
- Слева: конструктор
- Справа: живое превью в стиле Telegram

#### Шаг 3: Запуск
- Выбор аккаунтов (пул + резерв через drag-and-drop)
- Цели (chip-редактор)
- Тайминги (RangeField для задержек)
- Лимиты
- **Sanity-check панель**: «Всё готово? ✓ 4 аккаунта, ✓ 12 целей, ✓ сценарий»
- **CTA**: [Сухой прогон] [Запустить]

**Отличие**: у конкурента всё это в одну простыню; тут — линейная
прогрессия, невозможно забыть заполнить обязательное поле.

## 5. Ключевые компоненты

### 5.1 Split-view редактор сценария

**Главная фича**. Экран делится на две части:

```
┌────────────────────────────────┬─────────────────────────────┐
│ РЕДАКТОР                       │  ПРЕВЬЮ (Telegram-style)    │
│                                │                             │
│ ┌─ Роль: Инициатор ──────────┐ │  ┌──────────────────────┐   │
│ │ Характер: спрашивает вежливо│ │  │ @beauty_chat         │   │
│ │                            │ │  ├──────────────────────┤   │
│ │ ┌── Реплика #1 ──────────┐ │ │  │ ┌ Alice          ┐   │   │
│ │ │ «Ребята, посоветуйте  │ │ │  │ │ Ребята, посове- │   │   │
│ │ │  салон в центре?»    │ │ │  │ │ туйте салон...  │   │   │
│ │ │ ⏱ пауза 8с           │ │ │  │ └────────────────┘   │   │
│ │ └───────────────────────┘ │ │  │                      │   │
│ │ [+ добавить реплику]      │ │  │ ┌ Bob         ┐      │   │
│ └───────────────────────────┘ │  │ │ Была в Beauty│      │   │
│                                │  │ │ Zone, всё... │      │   │
│ ┌─ Роль: Ответчик ───────────┐ │  │ └─────────────┘      │   │
│ │ Характер: делится опытом   │ │  │                      │   │
│ │ ┌── Реплика #2 ──────────┐ │ │  │ ♥ 3    💬 продолжить │   │
│ │ │ «Была в Beauty Zone,   │ │ │  └──────────────────────┘   │
│ │ │  всё понравилось»      │ │ │                             │
│ │ │ ↩ ответ на #1  ⏱ 12с  │ │ │  💡 Диалог займёт ~35 сек   │
│ │ └───────────────────────┘ │ │                             │
│ └───────────────────────────┘ │  [Сгенерировать через ИИ 🪄] │
│                                │                             │
│ [+ добавить роль]              │                             │
└────────────────────────────────┴─────────────────────────────┘
```

- Слева — Kanban-подобный редактор: колонка на роль, внутри реплики
- Справа — превью, обновляется мгновенно
- Клик по реплике в любой из панелей — подсвечивает её в обеих
- **Отличие**: у конкурента превью — отдельный экран/модалка;
  у нас — всегда на виду

**Мобильная адаптация**: превью схлопывается в pinnable-полоску снизу,
разворачивается свайпом.

### 5.2 Bubble-редактор реплик

Каждая реплика — «баббл» в стиле Telegram с чипами настроек:

```
┌─── ⓘⓝ Инициатор ────────────────────────────────────┐
│                                                       │
│  «Ребята, посоветуйте проверенный салон красоты      │
│   в центре? Хочу что-то без ужасных цен...»          │
│                                                       │
│  [⏱ пауза 5-10с]  [↩ ответ на: —]  [#1]      [✎] [🗑]│
└───────────────────────────────────────────────────────┘
```

- Клик по тексту → inline-редактирование
- Клик по чипу «пауза» → mini-popover с двумя ползунками min/max
- Клик по чипу «ответ на» → селект других реплик
- Иконка `🪄` возле поля — «переписать через ИИ» (одиночный рерайт)

### 5.3 Chip-редактор целей

Вместо textarea:

```
┌─ ЦЕЛЕВЫЕ КАНАЛЫ ────────────────────── 12 добавлено ─┐
│                                                       │
│  ✓ @beauty_msk    ✓ @wellness_ru    ⏳ @beauty_pro   │
│  ✓ t.me/spa_chat  ⚠ @closed_ch     ✓ @lux_gram      │
│  ⚠ t.me/xxx       ...                                 │
│                                                       │
│  ┌────────────────────────────────────┐              │
│  │ + добавить: @username или t.me/... │              │
│  └────────────────────────────────────┘              │
│                                                       │
│  [Вставить списком]  [Импорт из файла]  [Из базы]    │
└───────────────────────────────────────────────────────┘
```

- Каждый канал — чип со **статусом резолва** (✓ / ⚠ / ⏳)
- Клик по ⚠ → показывает ошибку («не найден», «нет обсуждения», «уже в ЧС»)
- **Отличие**: у конкурента в textarea не видно, какие каналы валидны

```
┌── АККАУНТЫ ──────────────────────────────────────────┐
│                                                       │
│  ОСНОВНЫЕ (4)                    РЕЗЕРВ (2)          │
│  ┌────────────┐                  ┌────────────┐      │

│  │ роль:      │                  │            │      │
│  │ Инициатор ▼│                  │ 🟢 Фрэнк   │      │
│  └────────────┘                  └────────────┘      │
│  ┌────────────┐                                       │
│  │ 🟢 Bob     │                                       │
│  │ роль:      │                                       │
│  │ Ответчик ▼ │                                       │
│  └────────────┘                                       │
│                                                       │
```

### 5.5 Sticky launch-панель

Плавающая нижняя полоса на экране деталей:

```
├──────────────────────────────────────────────────────┤
│  ✓ Аккаунты 4/4   ✓ Сценарий OK   ⚠ Цели 0         │
│                        [Сухой прогон]  [🚀 Запустить] │
└──────────────────────────────────────────────────────┘
```

- Всегда виден чеклист готовности (в отличие от конкурента, где нужно
  скроллить до самого низа)
- Кнопка **Запустить** disabled, пока чеклист не полный
- При hover на ✗ — показывает, чего именно не хватает

## 6. Микровзаимодействия и анимации

- **Живая точка статуса**: у идущей кампании пульсирует зелёная точка
  (CSS `@keyframes pulse`)
- **Skeleton-loaders**: при загрузке списка кампаний показываем скелетоны,
  не спиннер
- **Optimistic updates**: клик по «Пауза» мгновенно меняет UI, откатывается
  при ошибке
- **Автосохранение onBlur**: как в `CampaignDetailScreen.tsx` (галочка
  «Сохранено» на 1.5с)
- **Haptic feedback** на мобильных: `haptic('light')` при переключении
  тумблеров и вкладок (уже есть в `shared/tg.ts`)
- **Плавные переходы табов**: `transition-all 200ms` для активного индикатора
- **Empty states**: у каждого пустого списка своя иллюстрация +
  подсказка следующего шага («Ещё нет целей — вставь ссылку выше»)
