# Telegram-Прайминг — UI / UX

Дополнение к `docs/priming-spec.md`. Экран/паттерн-уровень.
**Источник истины по стилю — `docs/UI-DESIGN-BRIEF.md`.** При любом
конфликте — побеждает бриф (палитра, радиусы, навбар зафиксированы).

Форм-фактор — Telegram Mini App, мобильный вертикальный. Никаких
трёхколоночных «десктоп-панелей», как у конкурента; десктоп получаем
даром через ширину body до 480px + центрирование. Раздел
«трёхколоночный layout» из `priming-spec.md` §12 переезжает в
«desktop overflow» (см. §7 этого файла) — но не приоритет.

---

## 1. Что мы НЕ повторяем за конкурентом

Референсы (скриншоты из ТЗ) — это плотная десктоп-панель:
неоново-оранжевый CTA «Купить модуль», два-три уровня насыщенных
градиентов, карточки с тенями, стеклянные подсветки, поля формы
на всю ширину, счётчики маленьким шрифтом сбоку.

У нас — противоположный полюс:

| Конкурент | Наш модуль |
|---|---|
| Оранжево-неоновый акцент | Один акцент `--accent = #F5F5F7` (белый) |
| Градиенты в фонах и кнопках | Матовые поверхности `--surface-1/2` + hairline |
| Плотная таблица параметров | Разреженные карточки-секции, 24–32 px gap |
| Много цветных статус-плашек одновременно | Точка-индикатор 8 px + мягкий бейдж только там, где решение |
| Тени под карточками | Hairline `rgba(255,255,255,0.07)` |
| Иконки цветные/с заливкой | Line, монохром, `--text-secondary` |
| «Купить модуль» — жёлто-оранжевая полоса | Пейволл — та же капсула, что у комментинга |
| «Заголовок раздела» = мелкий label | H1 28–34 px, `letter-spacing: -0.02em` |
| Live-логи спрятаны в футер | Live-лента — отдельный tab снизу, всегда доступна |

## 2. Токены (наследуем брифа, без изменений)

Используем именно то, что описано в `UI-DESIGN-BRIEF.md` §2. В модуле
не заводим новых цветов. Функциональные соответствия для прайминга:

- `--status-active` — цель `primed`, аккаунт `working`, кампания `running`.
- `--status-warning` — `cooldown`, `warming`, `flood_wait_pending`.
- `--status-critical` — `quarantined`, кампания `failed`, `USER_PRIVACY_RESTRICTED`.
- `--status-neutral` — `pending`, `draft`, `retired`.
- `--accent` — только: главный CTA («Запустить кампанию»),
  активный чип фильтра прогрева, выбранная строка в мультиселекте.

Никакого «фирменного оранжевого» под прайминг не заводим — модуль не
должен цветом кричать в общей сетке приложения.

## 3. Информационная архитектура

Три экрана верхнего уровня:

1. **Кампании** — список карточек + FAB «+».
2. **Кампания (детали)** — три таба: `Настройка · Ход · Логи`.
3. **Профили-пресеты (POC)** — переиспользуется другими модулями,
   поэтому живёт в общем разделе «Профили», а не внутри прайминга.

«Аудитория» и «Blacklist» — не отдельные корневые экраны, а drawer'ы,
которые вызываются из шага настройки. Это принципиально дешевле по
навигации, чем три вкладки конкурента.

│                                            │
│ [ cold · warm · hot · все ]                │   пилюли-фильтры (§6 брифа)
│                                            │
│ ┌─ карточка кампании ────────────────────┐ │
│ │ • Запуск по чату «AI news RU»          │ │   имя, вес 600, 17 px
│ │   running · 342 / 1 200 · privacy 6 %  │ │   14 px, --text-secondary
│ │                                        │ │
│ │   ●●●●●●●○○○  progress 28 %             │ │   linear thin bar
│ │                                        │ │
│ │   Аккаунтов 5 · флудвейтов 2 · сегодня 47│ │   tabular-nums, 13 px
│ └────────────────────────────────────────┘ │
│                                            │
│ (следующая карточка …)                     │
│                                            │
│                   ⬤ +                       │   FAB, --accent, 56 px

  плавает над капсульным навбаром с отступом 12 px.

## 5. Экран «Новая кампания» (визард)

Один экран-скролл, разбитый на секции-карточки. Не пошаговый визард
на весь экран — это дорого по кликам на мобильном, а у нас всего
6 секций. В самом низу — sticky CTA-капсула «Проверить и запустить».

Порядок секций:

### 5.1 Триггер (§5 спеки)

Секция с уникальной для нашего модуля преview-фичей — **мок-пуш**.

```
┌─ Триггер ──────────────────────────────────┐
│ Что увидит цель в уведомлении              │
│                                            │
│  ○  Автоудаление сообщений                 │
│  ●  Секретный чат  (по умолчанию)          │
│  ○  Добавили в контакты                    │
│                                            │
│  ┌──────── Preview (лочный экран) ───────┐ │
│  │ 🔒                                      │ │
│  │ Telegram · сейчас                       │ │
│  │ X пригласил вас в секретный чат         │ │
│  └────────────────────────────────────────┘ │
│                                            │
│  ⓘ Push реально приходит у 96 % клиентов.  │
└────────────────────────────────────────────┘
```

Preview — карточка `--surface-2`, 20 px радиус, hairline. Внутри —
имитация lock-screen: 4 px левая полоса `--surface-border-strong`,
имя приложения `--text-secondary`, тело `--text-primary`. Никаких
эмодзи-скинов iOS, никаких «синих кнопок Answer/Decline».

Это тот единственный момент, где у нас есть *визуальное* преимущество:
конкурент не показывает пользователю, что реально увидит цель.

### 5.2 Аккаунты

- Пилюли-фильтры прогрева: `cold · warm · hot`.
- Список карточек-строк аккаунта: `@username · phone · warm-day 12 ·
  primes today 22/40`.
- Мультиселект через тап (левая точка становится «✓» в квадрате
  10 px, но по правилу — квадрат не заливаем цветом, границу
  делаем `--surface-border-strong`, галочку — `--accent`).

### 5.3 Аудидория (drawer)

Кнопка-строка `Аудитория · 0 целей` открывает bottom-sheet drawer
на 90 % высоты. Внутри — табы «Парсер · CSV · Ручной». Каждый
рендерится как отдельная карточка. Итог парсинга — карточка-отчёт:

```
┌ Собрано ────────────────────────────────┐
│ raw           4 812                      │   tabular-nums 22/700
│ после фильтров 1 043                     │   --text-primary
│ ├ без username    2 118                 │   секции + бейджи
│ ├ боты/deleted      95                  │
│ └ уже в blacklist   58                  │
│                                          │
│ [ Использовать 1 043 ]                   │   CTA капсула --accent
└──────────────────────────────────────────┘
```

### 5.4 POC (профиль конверсии)

Мини-секция с превью «как будет выглядеть профиль для цели»:

```
┌ Профиль-пресет ────────────────────────────┐
│  ●●● (avatar 48px)                          │
│  Дмитрий Ковалёв                            │   17/600
│  @dima_reads                                │   13/500 --text-secondary
│  Читаю про AI · t.me/…                      │   bio
│  ────                                       │
│  📌 Канал «AI без воды»  (закреплено)       │   anchor
│  🎞 3 stories                                │
│                                             │
│  [ Изменить пресет ]                        │   вторичная кнопка
└─────────────────────────────────────────────┘
```

Секция кликабельная целиком — переход в редактор пресета.

### 5.5 Темп и лимиты

Секция с крупными числовыми контролами (никакой цепочки инпутов
в строчку, как у конкурента):

- **Между целями** — двойной thumb-slider `20…60 с` для hot,
  `200…600 с` для cold; над ним число tabular-nums 22/700.
- **Лимит на аккаунт в сутки** — stepper с крупным числом.
- **Пауза при флуд-лимите** — stepper.
- **Флуд-лимитов до карантина** — stepper.
- **Профиль прогрева** — пилюли `cold / warm / hot`, авто-подставляет
  значения выше.

Число — визуальный центр каждой строки; лейбл под ним `--text-tertiary`
12 px. Это принципиально отличается от конкурента, у которого числа —
самое мелкое в интерфейсе.

### 5.6 Humanizer

Секция-toggle: `off / balanced / aggressive` через сегмент-контрол
`--surface-2`, активный — `--surface-2` + `--surface-border-strong`
(не белая заливка — сегмент не главный CTA экрана).

Ниже — три чекбокс-строки: `Читать посты в каналах`, `Иногда ставить
реакции`, `Смотреть чужие stories`. Каждая — отдельная строка-строфа
с hairline снизу, checkbox справа.

### 5.7 Sticky footer

```
┌───────────────────────────────────────────┐
│  Готово к запуску: 5 акк · 1 043 цели      │   summary 13/500
│  [       Проверить и запустить      ]      │   full-width capsule
└───────────────────────────────────────────┘
```

Полноширинная капсула `--accent`, текст `--accent-on`. Если что-то не
готово — кнопка `--surface-2` disabled, а над ней алерт-карточка с
левой полосой `--status-warning` 4 px и текстом «Добавьте хотя бы
одну цель», как в брифа §7.

## 6. Экран «Кампания — Ход» (live)

Три таба сверху капсулой (не full-width): `Настройка · Ход · Логи`.

На «Ход»:

### 6.1 Хиро-KPI

Одна крупная карточка на всю ширину:

```
┌───────────────────────────────────────────┐
│  Отправлено сегодня                        │   13/500 --text-secondary
│  1 247                                     │   40/700 tabular-nums
│  из 40 × 5 акк = 200/день                  │   13/500 --text-tertiary
│  ▁▂▃▅▇▇▆▄▃▂  (спарклайн 24 ч, hairline)     │   1.5px --status-active
└───────────────────────────────────────────┘
```

Спарклайн — по правилам брифа §8: линия 1.5 px, лёгкая градиентная
заливка от `--status-active` к прозрачности 8 %, без сетки.

### 6.2 Ряд мини-KPI (горизонтальный скролл)

Карточки 140×88 px:

- «Успех» 92 % · `--status-active` точка.
- «Privacy» 6 % · `--status-warning` точка.
- «FloodWait» 2 % · `--status-warning`.
- «Карантин» 1 акк · `--status-critical`.

Каждая — `--surface-1`, hairline, 20 px радиус, число tabular-nums 28/700.

### 6.3 Строки-аккаунты

Ниже — список каждого аккаунта кампании как строка-карточка:

```
● @dima_reads      working    22/40 сегодня    next 42 с
● @lena_ai         cooldown   14/40             next 4 мин
● @pavel_notes     quarantine 3/40              ⓘ 3× flood
```

Цветная точка слева — статус. Ряд собран в одну карточку с hairline
между строками (см. бриф §4).

### 6.4 Кнопки управления

Не FAB и не в шапке — а sticky-панель как в списке. Слева
`⏸ Пауза`, справа `⏹ Стоп`. Обе — вторичные (`--surface-2`), красная
подложка появляется только при подтверждении (double-tap стоп).

## 7. Экран «Кампания — Логи»

Список карточек-событий, каждая — одна попытка прайминга.

Каждая строка: 4 px левая полоса цвета outcome + карточка
`--surface-1`:

```
│ ✓  @user123 → autodelete_on         primed         12:04:58
│ ⚠  @user456 → secret_chat           flood_wait 30 12:04:12
│ ✕  @user789 → contact_add           privacy       12:03:44
```

- Знак ✓/⚠/✕ — тонкая иконка line, монохром `--text-primary`.
- Цвет outcome живёт **только** в левой полосе, а не заливкой карточки.
- Тап по строке — bottom-sheet с деталями (raw response, latency).
- Верх экрана — панель фильтров-пилюль по outcome + input поиска.

Экспорт CSV — иконка в шапке (⤓), без крупной кнопки.

## 8. Профили-пресеты (POC редактор)

Отдельный экран под общим табом «Профили» приложения; сюда попадаем
из шага 5.4 или из бокового меню. Три секции:

1. **Личность** — имя, юзернейм, аватар. Слева-сверху крупный превью
   аватара 96 px с плюсом, справа — три поля.
2. **Bio** — textarea с автосчётчиком символов
   `70` в правом нижнем углу (`--text-tertiary`).
3. **Оффер** — три чекбокс-карточки:
   - `Anchor-канал` — раскрывается в форму (заголовок, аватар канала,
     тело поста, публичный/приватный).
   - `Stories` — grid-upload по 3 в ряд, drag&drop.
   - `Ссылка в Bio` — просто поле.

Кнопка «Сохранить и применить к N аккаунтам» внизу — CTA `--accent`.

## 9. Идеи «сделать лучше, чем у конкурента»

Каждая идея — самостоятельный tickable пункт, ни один не ломает бриф.

### 9.1 Preview-пуш (см. §5.1)
Показать целевой lock-screen прямо во время настройки. У конкурента
пользователь не понимает, что реально увидит цель — а это самое
интересное в модуле.

### 9.2 «Что произойдёт за час»
На финальном шаге запуска — карточка-симуляция:
`За первый час: ~34 прайма · ~2 flood_wait · рекомендуем стартовать
после 10:00 по гео`. Считается из warmup-профиля и текущих счётчиков.
У конкурента нет прогноза вовсе.

### 9.3 Auto-warmup ramp
Если аккаунт `cold`, кампания сама плавно поднимает `daily_limit` с
5 до 40 за 7 дней (график в UI показывает ступеньки). Конкурент даёт
только фиксированные цифры и предлагает пользователю руками менять.

### 9.4 Live-профиль
Второй preview в §5.4 — не статичный, а **интерактивный**: рендерит
профиль ровно так, как он будет виден целям сейчас (после применения
preset'а). Обновляется в реальном времени при правке.

### 9.5 A/B пресетов
На одну кампанию можно повесить 2 пресета (A/B), система сама
распределяет 50/50 и показывает conversion по attribution ссылке.
Ни у одного из известных конкурентов этого нет.

### 9.6 «Тихие часы» цели
Опция «не праймить получателей, у которых ночь в их таймзоне»
(вычисляется по last_seen + гео чата-источника). Уменьшает шанс
попасть в спам-жалобу.

### 9.7 Cross-module cooldown
Если тот же `tg_user_id` уже тегался в масс-тегинге или получал
шиллинг-комментарий за последние N дней — прайминг его пропускает.
У конкурента модули изолированы, наш плюс — общий cross-module
blacklist в БД.

### 9.8 Health-биометрия аккаунта
Мини-график «flood_waits / privacy / success» за 7 дней у каждого
аккаунта — прямо в его строке (§6.3), 40×16 px sparkline. Даёт
оператору мгновенно увидеть, кого пора выводить в retired.

### 9.9 «Один свайп → карантин»
Свайп-влево на строке аккаунта в live-панели → карантин + подпись
причины. Конкурент этого не даёт, у него только меню-⋯.

### 9.10 Экспорт «что уже сработало»
После кампании — экспорт CSV `tg_user_id, primed_at, source, preset,
account`, чтобы можно было ретаргетить по своему воронке (например,
слить в шиллинг-модуль как «прогретый» сегмент). Конкурент — только
статистика внутри UI.

### 9.11 Клавиатурный shortcut в Mini App
`⌘ + пробел` / long-press на FAB — открывает быстрый запуск последней
кампании с той же аудиторией. Ускоряет ежедневный рутинный запуск.

---

## 10. Desktop overflow (не приоритет)

Если модуль откроют в веб-версии на широком экране — центрируем body
до 480 px, слева и справа отдаём пустоту цвета `--bg-base`. Никаких
трёхколоночных десктоп-layout'ов и «правого live-rail». Это специально
и осознанно: приложение позиционируется как Mini App, десктоп —
не первичный форм-фактор.

## 11. Инструкция для фронтенд-промптов модуля

В начало любого промпта, генерящего компонент прайминга:

```
Прочитай docs/UI-DESIGN-BRIEF.md И docs/priming-ui.md ПЕРЕД тем как
писать любой компонент. При конфликте побеждает UI-DESIGN-BRIEF.md
(палитра, радиусы, навбар), затем priming-ui.md (структура экранов
модуля). Плагин frontend-design используем как дополнение по общему
качеству (иерархия, отступы, consistency) — не поверх палитры.
```
