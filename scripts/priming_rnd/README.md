# priming_rnd — R&D по MTProto-триггерам прайминга

Инструмент для этапа 0 из `docs/priming-prompts.md`. Гоняет по одному
кандидату из `docs/priming-spec.md §5` на паре живых тестовых аккаунтов
и собирает JSON-отчёты, из которых потом собирается матрица в
`docs/priming-triggers.md`.

## Что делает

1. Открывает клиент аккаунта A через штатный `worker.client_pool.ClientPool`
   (значит: тот же прокси, фингерпринт, шифрование сессии).
2. Через `around_telethon_call` (health/flood-инструментация) вызывает
   один MTProto-метод, направленный на аккаунт B.
3. Спрашивает у оператора вручную:
   - пришёл ли push у аккаунта B;
   - остался ли в чате видимый артефакт (сообщение / служебка);
   - произвольные заметки.
4. Складывает отчёт в `scripts/priming_rnd/reports/<ts>_<action>.json`.

## Что нужно подготовить

- Два тестовых Telegram-аккаунта, **уже загруженных в БД** штатным потоком
  (с прокси, фингерпринтом, зашифрованной сессией). R&D-скрипт не создаёт
  сессии сам — это принципиально, чтобы прогон шёл через тот же контур,
  что и продакшн.
- Аккаунт B должен иметь `username` (или передавайте peer вручную через
  `--target`).
- Второй физический клиент/телефон, залогиненный в аккаунт B, — чтобы
  наблюдать push и артефакт в чате.

## Запуск

```bash
python -m scripts.priming_rnd \
    --action secret_chat_request \
    --account-a 42 \
    --account-b 43
```

Кандидаты (см. `actions.REGISTRY`):

- `set_ttl_1d`, `set_ttl_off`
- `secret_chat_request`
- `contact_added`, `contact_removed`

## Что делать с отчётами

После набора отчётов заполните таблицу в `docs/priming-triggers.md`
(колонки: `trigger_action | mtproto | push_seen | chat_artifact | notes`)
и отметьте 2–3 самых надёжных как «MVP-кандидаты».
